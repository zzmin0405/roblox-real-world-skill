# 현실 공간의 Roblox 재현

실제 장소를 걸을 때의 거리감·실루엣·연결·시선을 재현한다. 도시 모델 가져오기와 실경 완성을 구분하고, 근거 없는 유사도 점수나 완전 자동 복제를 약속하지 않는다. 대상 프로젝트의 지시와 기존 제작 체계를 따른다. 이 스킬은 특정 도시·MCP 서버·유료 서비스에 의존하지 않는다.

## 시작 판단

기존 자료·장면·검수 결과부터 확인한다. 새 변환기를 만들기 전에 [기존 공개 도구](references/sources-and-rights.md#기존-공개-도구)를 평가하고 현재 제작 체계에 필요한 부분만 활용한다. 장소와 범위를 아직 모르면 **재현할 위치 또는 지도 링크와 시작·끝 동선**을 먼저 묻고, 답변과 무관한 도구·자료 확인을 진행한다. 나머지 값은 기존 설정이나 명시한 가정으로 시작한다.

- 장소의 경계, 시기·계절·시간대, 외부/실내 범위, 대표 도착점과 다음 길을 정한다. 공개 자료의 최신 날짜와 사용자가 원하는 재현 시점을 구분한다.
- 아바타 크기, 이동 속도, 카메라 높이·FOV, 대상 기기, 실제 실행 파일과 소스 소유 범위를 확인한다. 수치를 바꿔 외관 오류를 감추지 않는다.
- 개선 요청이면 현재 Play와 실경 사이의 **가장 큰 차이와 기대 변화**를 먼저 특정한다. 길·강·지면·주요 건물의 기반 실패가 있으면 그것과 선행 자료·정합을 우선한다.
- 연결된 공식 Studio 도구를 우선 사용한다. 실제 제공된 기능만 호출하고, 도구가 없으면 사용 가능한 Studio UI·프로젝트 경로로 진행한다. 불가능한 관찰은 미검증으로 남긴다.

전체 요청 범위를 유지하면서 작은 연결 구간에서 제작 방식을 먼저 확인한다. 약 100~300m는 착수 예시이며 완료 범위를 임의로 줄이는 기준이 아니다. 부분 수정에는 직접 영향받는 항목만 적용한다.

## 1. 사용할 수 있는 근거 확보

자료를 새로 고르거나 배포할 때 [자료와 이용 조건](references/sources-and-rights.md)을 읽는다. 같은 범위의 기존 자료를 재사용하고, 범위·시기 변경이나 충돌이 있을 때만 보완한다.

| 근거 | 주로 확정하는 것 | 그대로 믿지 않는 것 |
|---|---|---|
| 허용된 지상 사진·360도·자체 촬영 | 보행 시점의 입면·입구·차선·난간·계단·가림 | 가려진 면·실내·정밀 치수·현재 교통량 |
| 허용된 항공·정사영상 | 도로·건물 윤곽·양안·교량의 평면 배치 | 문턱·교각·높이·입면 |
| 측량·도시 모델·LiDAR·DEM | 좌표·표고·기본 형상과 관측 범위 | 낮은 LOD에 없는 처마·창·교량 아래·현재 모습 |

각 자료의 원본 URL, 공급자·촬영자, 촬영/측량 시기와 확인일, 범위, 좌표·표고 기준, 해상도/LOD, 이용 조건과 표시 의무를 기존 작업 기록에 연결한다. 열람·분석·파생 모델 제작·텍스처 이용·재배포 권한을 같은 것으로 취급하지 않는다. 권리가 불명확한 자료 대신 허용된 자료로 진행하고, 그 때문에 확정하지 못한 면은 표시한다.

## 2. 같은 공간으로 정합

좌표·지면·가져오기 문제를 다룰 때 [공간 구성과 정합](references/spatial-and-studio.md)을 읽는다.

- 위경도·투영좌표·축 순서·단위·수직 기준을 구분하고, 건물·지면·사진마다 다른 기준을 먼저 맞춘다. 위경도를 미터처럼 빼거나 Web Mercator 길이를 무보정 실측으로 쓰지 않는다.
- 작은 로컬 원점을 두고 수평면에 고르게 분포한 비공선 기준점 3개 이상으로 방향·축척을 확인한다. 같은 점을 맞춘 잔차와 별도 지점의 검증을 구분한다.
- 표준 단위와 프로젝트의 실제 import 크기를 모두 확인한다. 1m 검증 물체와 알려진 도로 폭으로 중복 축척·축 반전·높이 오류를 가른다.
- 투영된 미터 좌표와 Roblox 대응점이 있으면 `scripts/fit_local_frame.py`를 사용할 수 있다. 이 도구는 수평 유사 변환만 계산하며 CRS 재투영·표고·실경 정확도를 판정하지 않는다. 입력과 사용법은 위 참조 문서에 있다.

## 3. 장면의 기반 제작

사용자가 요청한 거리 전체에서 차도·보도·교차로·연속 건물군·수로·양안·다리·주요 지물의 위치와 연결을 먼저 구성한다. 주요 건물 누락을 임의 건물로 채우지 않는다. 확보된 실측 건물 배치는 미확정 수위와 구분해 진행할 수 있다.

지면의 각 경계를 포장·건물 기초·옹벽·자연 지형·수면 중 누가 담당하는지 정한다. DEM 높이장 하나로 수직 호안·오버행·교량 아래·터널을 덮지 않는다. 실제 문턱과 외부 보행면으로 접속하고 건물 최저점을 외부 지면으로 간주하지 않는다. 물·건물 전체 이동으로 틈·관통·매몰을 숨기지 않는다.

도시 데이터의 벽 없는 차양·개방 구조물 분류를 보존한다. 보행 충돌은 시각 메시와 필요에 따라 분리하되 개방 통로를 닫힌 충돌 체적으로 막지 않는다. 실제 아바타와 카메라가 끝까지 통과하는지 확인한다.

Studio에서 지형·배치·충돌을 조립한다. Blender 등 외부 도구는 필요한 개별 지붕·곡면·UV 제작에 사용한다. 기존 프로젝트가 정한 동기화 체계를 보존하고 Studio 편집 영역과 생성기/Rojo 관리 영역을 겹치지 않게 한다. 전환 전에 저장본을 보존한다.

## 4. 보행 거리의 표현과 경험

대표 Play 시점에서 기반이 맞는지 확인한 뒤 근접 입면·처마·난간·표지·재질을 보완한다. 원근이 들어간 사진을 여러 면에 늘려 붙이지 않는다. 허용된 텍스처의 시점·가림·스케일을 확인하고 재투영·보정하거나 해당 면을 따로 제작한다. 근거가 없는 형상·글자는 확정하지 않는다.

AI 생성은 필요할 때 개별 에셋 하나로 시험한다. 서비스·참조·크기·작업 ID·비용을 남기고 실측 에셋과 구분한다. 실루엣·UV·충돌·재질 비용을 대표 Play에서 평가한다. 실패 원인이 같으면 프롬프트 반복 대신 실측 메시·Studio 부품·개별 모델링으로 바꾼다.

전체 제작은 장소 발견·이동·돌아오기, 필요한 안내 UI와 환경음을 구간에 함께 완성한다. 실제 입력으로 조작하고 실제로 소리를 듣는다. 전체 제작과 관계없는 재화·전투·상점을 추가하지 않는다. 기존 `roblox-experience-quality` 스킬이나 프로젝트 품질 규칙이 있으면 해당 범위에 함께 적용한다. 그것이 없어도 아래 완료 조건을 유지한다.

## 5. 같은 시점에서 확인하고 보존

1. 수정 전/후와 실경의 위치·방향·카메라 높이·FOV를 가능한 한 맞춘다. 캡처 때 실제 카메라 위치·방향·FOV·뷰포트 크기를 읽어 확인한다. 사용자 카메라가 일회성 지정을 덮어쓰면 비교 중에만 카메라를 고정하고 실제 입력 검수 전에 해제한다. 촬영 조건의 근사와 시기 차이를 밝힌다. 새 구간 완료에는 도착·근접·연결부를 확인한다. 부분 수정은 영향 시점을 확인한다.
2. 현재 빌드의 실제 Play에서 길·주요 실루엣·연속 건물군·지면·양안·재질을 한 장면으로 대조한다. 항공 시점·로컬 렌더·로그·파트 수로 보행 외관을 통과시키지 않는다.
3. 실제 입력으로 시작점부터 다음 구간까지 이동한다. 좁은 길·차양 아래·교량 접속부·낙하 복구·스트리밍 재진입을 관련 범위에서 확인한다. 체력과 이동 상태만으로 통과를 판정하지 않는다.
4. 후보 적용 → 관찰 → 채택한 소스와 실행 파일 보존 또는 실험 원복까지 연결해 수행한다. 변경 요청 시간 초과 후에는 실제 상태를 조회하고 중복 전송하지 않는다. 생성·추출 실패 후 이전 소스로 빌드하지 않는다.
5. 큰 차이가 줄지 않으면 같은 접근의 상세 추가·일괄 등록을 멈추고 원인을 바꾼다. 원복은 실험의 종료이며 목표 결함의 해결은 아니다. 가능한 다음 실질 수정을 계속한다. 관찰로 검증한 독립 개선은 보존하고 새 결함이 생긴 부분만 되돌린다.

저사양 대응은 핵심 배치·실루엣을 보존하면서 메시·재질 재사용, LOD, 스트리밍, 충돌 단순화, 그림자·투명 비용을 조절한다. 가장 부하가 큰 보행 구간을 대상 실기기에서 측정한다. 기기·그래픽 설정·인원·측정 구간·프레임 시간과 멈춤을 남긴다. Studio 에뮬레이션은 모바일 실기기 성능의 근거가 아니다.

## 완료와 전달

프로젝트의 기존 기록을 갱신하고 새 작업마다 버전 place·빈 체크리스트·일지를 늘리지 않는다. 자동 검사가 있으면 기록 일치를 확인하는 데 사용하며 시각 판정을 맡기지 않는다.

다음 항목을 구분해 한국어로 보고한다.

- **단계:** 진단 / 후보 제작 / Play 임시 적용 / 본게임 개선 반영. 마지막 전달 이후 본게임에 실제 남은 변화를 적는다.
- **근거:** 검수한 경로와 대표 시점, 실제 실행 파일·소스, Play 화면·입력·청취·실기기 측정의 위치와 조건.
- **남은 차이:** 미확정 형상·빈 건물·지면 단절·외관 실패와 미검증 항목. 자료·기기·도구 부재는 구체적으로 적고 가능한 독립 작업을 진행한다.
- **판정:** 기능, 에셋 표시, 실경 외관, 모바일 성능을 나눠 판단한다. 대상 범위의 필수 실패·미검증이 남아 있으면 그 범위의 완료를 선언하지 않는다.

전달 전 채택한 소스, 단일 주 실행 파일, 현재 Play의 반영을 확인한다. 디스크 빌드가 갱신됐다는 이유로 열린 Studio도 갱신됐다고 가정하지 않는다. 한 구간의 통과를 도시 전체의 완성으로 확대하지 않는다.
