# 공간 구성과 Studio 작업

좌표 정합, 지면 접속, 가져오기 또는 성능 문제가 있을 때 필요한 절만 읽는다.

## 좌표와 크기

원본마다 CRS 식별자, 좌표 축 순서, 단위, 표고 기준을 확인한다. GIS의 x/y가 easting/northing과 항상 같지는 않다. 일부 일본 평면직각좌표 자료의 X/Y는 북/동 순서다. CityGML의 `srsName`·차원·축 순서와 변환기의 해석을 확인하고, 필요한 재투영은 GIS 도구나 해당 CRS를 지원하는 라이브러리에서 수행한다.

로컬 범위의 미터 투영좌표를 사용한다. 큰 지구 좌표는 원점을 뺀 뒤 Roblox로 옮긴다. 프로젝트의 기존 축 관례가 없다면 동=+X, 위=+Y, 북=-Z로 시작하고 회전값을 별도 보존한다. 축척은 수평·수직에서 일치시킨다. 높이를 의도적으로 과장했다면 실측 재현과 구분한다.

Roblox 공식 표준은 1 stud=0.28m다. 프로젝트가 다른 스케일을 사용하면 그 값과 이유를 유지한다. 가져오기 도구가 이미 단위를 변환했는지 1m 검증 물체로 확인한 뒤 추가 변환한다. 아바타 키, 카메라 높이, 이동 속도가 현실 거리감에 영향을 주므로 알려진 거리·도로 폭을 걷고 확인한다. FOV를 바꿔 건물 간격 오류를 가리지 않는다. [공식 단위](https://create.roblox.com/docs/physics/units)

정합점은 구간 양끝과 횡방향에 고르게 둔다. 같은 건물 모서리만 몰아 쓰거나 일직선 도로 중심점만 쓰지 않는다. 잔차가 큰 경우 CRS·축 순서·단위·기준점 매칭부터 가르고, 임의로 건물을 각각 옮겨 잘못된 전체 변환을 숨기지 않는다. 정합에 사용하지 않은 별도 점과 알려진 치수도 확인한다.

## 수평 정합 도우미

Python 3.10 이상이며 외부 패키지는 필요 없다. 입력은 이미 같은 CRS로 변환된 **미터 단위 투영좌표**와 그에 대응하는 Roblox X/Z다. 실제 표고, 위경도 변환, 지오이드 보정, 세로 Y는 계산하지 않는다. 임계값은 프로젝트의 허용 오차로 정한다.

설치된 `roblox-real-world` 스킬 폴더를 작업 디렉터리로 열고 실행한다. 저장소에서 시험하면 먼저 `skills/roblox-real-world`로 이동한다.

```sh
python scripts/fit_local_frame.py assets/control-points.synthetic.json --max-error-studs 0.01
```

스킬에 포함된 `assets/control-points.synthetic.json`은 실제 장소가 없는 합성 격자다. 실제 입력은 다음 형태로 만든다.

```json
{
  "crs": "LOCAL:synthetic-metre-grid",
  "coordinate_type": "projected",
  "units": "m",
  "control_points": [
    {"id": "A", "easting": 0, "northing": 0, "x": 0, "z": 0},
    {"id": "B", "easting": 28, "northing": 0, "x": 100, "z": 0},
    {"id": "C", "easting": 0, "northing": 28, "x": 0, "z": -100}
  ]
}
```

`crs`에는 실제 사용한 투영좌표계 또는 정의된 로컬 미터 격자를 적는다. 이 도구는 CRS 정의를 검증하거나 재투영하지 않으므로 EPSG 이름만 바꿔 다른 좌표를 넣지 않는다. `easting/northing` 키가 축의 의미다. 원본의 X/Y를 그대로 복사하기 전에 축 순서를 확인한다.

stdout의 JSON에는 변환과 각 기준점 오차가 나온다. 종료 코드 0은 계산 성공, 1은 입력/계산 오류, 2는 지정 최대 오차 초과다. **코드 0은 장소 재현 합격이 아니다.** 출력의 진단과 별도 검증점을 확인한 뒤에만 제작 설정으로 채택한다. 실패 출력을 주 설정 파일에 셸 리다이렉션으로 덮어쓰지 않는다.

## 표고와 지면

타원체고와 표고를 섞지 않는다. 표고 기준·기준점·오프셋·취득 시기를 보존한다. 물높이는 같은 날짜의 증거·호안 단면과 함께 확인하고 DEM 최저점으로 정하지 않는다. 표고가 미확정인 부분은 작업용 후보로 분리한다.

| 경계 | 제작 원칙 | Play 확인 |
|---|---|---|
| 건물–보도 | 실제 문턱·외부 포장으로 접속, 기초 최저점과 구분 | 입구 앞 매몰·단차·관통 |
| 호안–수면–강바닥 | 상단·하단·수직벽을 별도 구조로 연결 | 다리 아래 허공·수면 단절·가짜 흙비탈 |
| 다리–양안 | 상판·교각·하부 통로·접속 보도 분리 | 접속부 틈·머리/카메라 충돌 |
| 차양·개방 구조 | 원본의 개방 분류·빈 공간 유지 | 차양 뒤까지 실제 통과 |

DEM/Terrain은 자연 지형에 적합하다. 단일 높이장은 같은 평면 좌표의 여러 높이·수직벽·오버행을 표현하지 못한다. 도시 접속부는 필요한 메시·부품·충돌 면을 함께 구성한다. 얇은 장식 면으로 큰 지형 실패를 숨기지 않는다.

Terrain을 지워도 같은 영역의 Part·MeshPart 지면은 남는다. 구조화한 호안 위로 예전 지면이 보이면 실제 면을 찍어 소유 레이어를 확인하고, 새 경계와 중복되는 원본 면만 잘라낸다. 경사진 면을 법선 방향으로 두껍게 늘린 받침도 평면 경계를 넘을 수 있으므로 상면뿐 아니라 지지체의 외곽을 확인한다.

## 소스와 Studio

프로젝트가 사용 중인 Studio 편집·Rojo·생성기의 경계를 먼저 확인한다. 생성 대상으로 삼을 모델과 수작업 구역을 분리하고 전환 전에 저장한다. 단일 주 place와 실제 소스의 대응을 유지한다. 프로젝트에 빌드 스크립트가 있으면 재사용하되 특정 로컬 경로나 Studio ID를 스킬에 고정하지 않는다.

처음에는 대표 개별 에셋으로 단위·축·원점·재질·알파·UV·법선·충돌·표시 권한을 확인한다. 구조가 검증되기 전에 전체 구간을 일괄 업로드하지 않는다. 가져오기 제한은 자주 바뀌므로 현재 [Importer 문서](https://create.roblox.com/docs/studio/importer)를 확인한다. 업로드 권한과 실행 experience의 에셋 소유·사용 권한은 별도로 확인한다.

시각 메시의 모든 면을 정밀 충돌에 사용하지 않는다. 보행면·벽·난간의 실제 용도에 맞게 단순화하고 통로는 열어 둔다. 정적 부품 고정, 장식의 충돌·쿼리·터치 용도 분리는 실제 게임 기능에 맞춘다.

## 모바일의 표현 비용

먼 건물은 실루엣을 남기는 LOD, 가까운 면은 선명한 재질, 반복 부품은 메시·사진을 재사용한다. 텍스처 해상도·재질 수·투명 겹침·광원/그림자·충돌과 스크립트 비용을 관측에 따라 줄인다. 임의의 파트 수·삼각형 수 하나를 모든 기기의 합격선으로 쓰지 않는다.

큰 구간은 [Streaming](https://create.roblox.com/docs/workspace/streaming)을 검토하되 빠른 이동·리스폰·구간 재진입·느린 로딩에서 길이 사라지거나 캐릭터가 떨어지지 않는지 확인한다. 항상 유지되는 대형 모델로 Streaming의 효과를 지우지 않는다. 성능 측정은 [MicroProfiler](https://create.roblox.com/docs/performance-optimization/microprofiler) 등 현재 제공 도구를 사용한다. Studio 화면 크기 변경과 PC 측정으로 모바일 실기기 결과를 대신하지 않는다.
